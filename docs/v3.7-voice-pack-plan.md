# v3.7.0 — Pre-Recorded Voice Pack Plan

**Problem**: v3.6.7 uses Android `TextToSpeech` to speak the time, which falls over constantly on Xiaomi/Huawei/Meizu devices (no Google TTS installed, `attributionTag` warnings, robotic child voices, killed in the background). For a clock app meant for kids, the experience is rough.

**Conclusion**: Ditch the on-device TTS engine entirely and switch to a **cloud-pre-rendered full-sentence child-voice audio pack**, played at runtime directly by `MediaPlayer`.

---

## Plan Overview

```
┌─────────────────────────────────────────────────────────────┐
│  app/src/main/assets/voice/                                 │
│    ├── girl/                  ←— 👧 Girl (XiaoyiNeural)     │
│    │   ├── zh/                                              │
│    │   │   ├── am/0100.ogg .. 1259.ogg   (720)              │
│    │   │   ├── pm/0100.ogg .. 1259.ogg   (720)              │
│    │   │   └── manual/0100.ogg .. 1259.ogg (720)            │
│    │   └── en/                                              │
│    │       ├── am/    (720)                                 │
│    │       ├── pm/    (720)                                 │
│    │       └── manual/(720)                                 │
│    └── boy/                   ←— 👦 Boy (YunxiaNeural)      │
│        └── (same structure)                                 │
└─────────────────────────────────────────────────────────────┘
8,640 OGG/Opus files, ~5–9 KB each, ~75 MB total
```

**3 sentence templates**:

| Bucket | Chinese template | English template | When used |
|--------|------------------|------------------|-----------|
| `am`     | 现在是上午 X 点 Y 分 | It's X:YY AM. | Auto mode + 12h + AM |
| `pm`     | 现在是下午 X 点 Y 分 | It's X:YY PM. | Auto mode + 12h + PM |
| `manual` | X 点 Y 分 (no prefix) | X o'clock / X:YY (no AM/PM) | When the dial is set manually |

On the hour we say "X 点整" / "X o'clock" to avoid saying "zero minutes".

## Choices

**TTS engine**: Microsoft Edge TTS (the `edge-tts` Python package)
- Free, no API key required
- Neural-network child voices, far better than the system TTS
- One-shot server-side rendering — the APK has zero runtime network dependency

**Voices**:

| Role | Chinese voice | English voice | Rate |
|------|---------------|----------------|------|
| 👧 Girl | `zh-CN-XiaoyiNeural` (cartoon-y, lively) | `en-US-AnaNeural` (child voice) | −8% |
| 👦 Boy  | `zh-CN-YunxiaNeural` (cute child voice)  | `en-US-AndrewMultilingualNeural` (warm) | −5% |

**Encoding**: OGG/Opus 24 kbps mono, voip-mode (speech-optimized)
- ~5–9 KB per file (vs. ~15–25 KB original MP3 — 56% smaller)
- Natively supported by Android `MediaPlayer`, no third-party decoder
- APK config: `androidResources { noCompress.add("ogg") }`
  - Stops aapt from double-compressing assets that are already Opus (CPU waste, near-zero gain)

## Runtime Architecture

```
ClockScreen — user taps 🔊
   │
   ▼
SmartTtsManager.speakTime(hour, minute, isPm, language, gender, mode, …)
   │
   ├─► PreRecordedTtsPlayer.playTime(…)
   │        │
   │        ├─ Build path: voice/<gender>/<lang>/<period>/HHMM.ogg
   │        │   period = manual | am | pm
   │        │
   │        ├─ Asset missing / 24h mode / showing seconds → return false
   │        │
   │        └─ Asset present → MediaPlayer.start()  ✅
   │
   └─► (on miss) TtsManager.speak(…)  system TTS fallback (24h / showSeconds only)
```

**Key files**:
- `util/PreRecordedTtsPlayer.kt` — core asset player (MediaPlayer wrapper)
- `util/SmartTtsManager.kt` — pre-rec → system-tts routing layer
- `util/TtsManager.kt` — legacy engine (kept as the 24h / seconds-mode fallback)

   - `👧 Girl / 👦 Boy` (English) or `👧 小姐姐 / 👦 小哥哥` (Chinese)

## Coverage

| Scenario | Pre-recorded? | System TTS? |
|----------|---------------|-------------|
| 12h + no seconds + auto mode | ✅ via am/pm bucket | — |
| 12h + no seconds + manual mode | ✅ via manual bucket | — |
| 12h + show seconds | ❌ | ✅ |
| 24h | ❌ | ✅ |

> Show-seconds / 24h modes stay on system TTS because:
> a) those combinations are not the default experience (default is 12h, no-seconds)
> b) pre-rendering them all would double the APK increment (another 22+ MB)
> c) MIUI users typically stick to the defaults, so the main path already sidesteps every system-TTS problem

## Generation Pipeline

Build script: `/home/azureuser/.openclaw/workspace/clock-poc/generate_voice_pack.py`

Usage:
```bash
python3 generate_voice_pack.py \
    --output voice-pack \
    --voices girl,boy \
    --concurrency 14
```

- Concurrency 14 (edge-tts is network-bound — pushing higher doesn't help)
- Existing ogg files are skipped automatically (incremental re-runs)
- Transcoded to Opus 24k via ffmpeg

A full girl+boy run (8640 files) takes ~25 minutes.

To add a voice: append an entry under `VOICES = {...}` and re-run the script.

## Known Trade-offs

1. **APK grows from 10 MB → 76 MB**: mostly the 75 MB voice pack. That's the cost of Bluey-friendly child voices. To shrink: ship one voice only (−24 MB) or drop the manual bucket (−22 MB).
2. **24h / seconds modes still depend on system TTS**: see "Coverage" above.
3. **Fixed timbre**: edge-tts neural voices are a single "person", so intonation is identical across every time stamp — an upside (zero seam between clips) but it rules out human-recorded emotional variation.
